Animations bring your backgrounds to life with CSS keyframes. This page documents every animation, its options and how to combine them.

> **Note:** animations need the xeerpe stylesheet. If you have not added it yet, see [Setup](#setup).

## Overview

xeerpe ships nine animations: `pulse`, `rotate`, `breathe`, `aurora`, `shimmer`, `liquid`, `plasma`, `float` and `drift`. Each one is a `Builder` method, so you add it to the chain like any other layer.

```ts
import { Builder } from 'xeerpe'

const style = new Builder()
  .radialGradient({
    from: '#34d399',
    to: '#052e1c',
  })
  .pulse()
  .toStyle()
```

An animation does not add a background layer. It adds one `animation` property to the style returned by `toStyle()`, which points to a keyframe animation defined in the xeerpe stylesheet.

The same animation can also be added with the generic `animation()` method, which takes the animation name and its options. In this form the options are required, so pass an empty object to use the defaults.

```ts
new Builder()
  .animation('pulse', {})
  .toStyle()
```

Animations act on one of two targets:

- **The background:** `breathe`, `aurora`, `shimmer` and `drift` scale or move the background. `liquid` does both, and also shifts its hue.
- **The whole element:** `pulse`, `rotate`, `float` and `plasma` affect the element and everything inside it, text included.

---

## Setup

The keyframes live in a stylesheet that you load once, in the entry file of your app.

```ts
import 'xeerpe/animations.css'
```

> **Note:** without the stylesheet the style is applied but nothing moves, and the browser reports no error. For CSS, SCSS and Angular setups, see [Add the stylesheet](/guide/installation#add-the-stylesheet).

All keyframes are prefixed with `xeerpe-`, so they never collide with your own animations.

## Shared options

Every animation accepts the same four options, plus `target` on the five that move the background. Each animation has its own defaults, listed in its section below.

<Prop name="duration" type="string">

    How long one cycle takes, as a CSS time such as `'4s'` or `'800ms'`.

</Prop>

<Prop name="easing" type="string">

    The timing function, for example `'linear'`, `'ease-in-out'`, `'cubic-bezier(0.4, 0, 0.2, 1)'` or `'steps(4)'`.

</Prop>

<Prop name="direction" type={["'normal'", "'reverse'", "'alternate'", "'alternate-reverse'"]}>

    Whether the animation plays forward, backward or alternates between the two. Only `pulse` and `aurora` use it. The other animations ignore it.

</Prop>

<Prop name="iterationCount" type={["number", "'infinite'"]}>

    How many times the animation runs. Use a number to play it a fixed number of times, or `'infinite'` to loop forever.

</Prop>

<Prop name="target" type={["'gradients'", "'patterns'", "'all'"]}>

    Which layers of the background the animation moves. `'gradients'` is the default: the gradients move and patterns and effects stay in place. `'patterns'` moves only the patterns, over a still gradient. `'all'` moves every layer. Only `breathe`, `aurora`, `liquid`, `shimmer` and `drift` use it, and `'patterns'` only has an effect on the ones that move the background (`shimmer`, `drift` and `liquid`). Any other value throws an error.

</Prop>

> **Note:** `pulse`, `rotate`, `float` and `plasma` have no `target`. They change a property of the whole element (`opacity`, `transform` or `filter`), which CSS cannot apply to one layer only, so they always affect everything.

> **Note:** apart from `target`, the values are inserted into the CSS as they are, without validation. If a value is not valid CSS, for example a duration without a unit, the browser ignores the whole `animation` declaration and nothing moves.

### Example

Every option is optional, and any you leave out keeps the default of the animation.

```ts
new Builder()
  .radialGradient({
    from: '#34d399',
    to: '#052e1c',
  })
  .pulse({
    duration: '2s',
    easing: 'ease-in',
    direction: 'reverse',
    iterationCount: 3,
  })
  .toStyle()
```

The code above produces this `animation` value:

```css
animation: xeerpe-pulse 2s ease-in reverse 3
```

## Pulse

Fades the element between full opacity and 70% opacity, which makes it breathe softly. It changes the opacity of the whole element, content included, so the page behind shows through.

### Defaults

```ts
{
  duration: '4s',
  easing: 'ease-in-out',
  direction: 'alternate',
  iterationCount: 'infinite',
}
```

### Examples

#### Pulsing glow

A radial glow that fades in and out.

<XeerpeDemo example="pulse-glow" />

```ts
new Builder()
  .radialGradient({
    from: '#34d399',
    to: '#052e1c',
    colorToPosition: '75%',
  })
  .pulse({ duration: '3s' })
  .toStyle()
```

## Rotate

Spins the element a full turn around its center. It rotates the whole element and its content, so it works best on a square or round element.

### Defaults

```ts
{
  duration: '12s',
  easing: 'linear',
  iterationCount: 'infinite',
}
```

### Examples

#### Color wheel

A conic gradient on a round element becomes a spinning color wheel.

<XeerpeDemo example="rotate-conic" width="180px" height="180px" borderRadius="50%" />

```ts
    ],
  })
  .rotate({ duration: '8s' })
  .toStyle()
```

## Breathe

Zooms the background in and out, from 100% to 200% of its size and back. At its largest the background is magnified, so the details of the gradient spread out.

### Defaults

```ts
{

  easing: 'ease-in-out',
  iterationCount: 'infinite',
}
```

### Examples

#### Breathing mesh

The blobs of a mesh gradient swell and shrink.

```ts
      {

        to: 'transparent',
        position: '70% 100%',
        colorToPosition: '60%',
      },
    ],
  })
  .breathe({ duration: '8s' })
  .toStyle()
```

## Shimmer

Slides the background horizontally, from right to left, which produces a moving highlight. It is the classic loading skeleton effect.

For a clean loop, the gradient needs three things:

- **A wider background:** a gradient needs to be larger than the element, otherwise there is nothing to slide. When you do not set a `backgroundSize` on the gradient, `shimmer` widens it to `'200% 100%'` for you. Set your own value, such as `'400% 100%'`, to control how far the band travels.
- **The same color at both ends**, because the background repeats and a different color would leave a visible seam.
- **A horizontal direction** (`90deg`), so the band travels in the same direction as the animation.

### Defaults

```ts
{
  duration: '3s',
  easing: 'linear',
  iterationCount: 'infinite',
}
```

### Examples

#### Loading skeleton

A lighter band that travels across a dark surface.

<XeerpeDemo example="shimmer-skeleton" />

```ts
new Builder()
  .linearGradient({
    colors: ['#1e293b', '#475569', '#1e293b'],
    angle: '90deg',
    backgroundSize: '200% 100%',
  })
  .shimmer({ duration: '2.5s' })
  .toStyle()
```

## Liquid

Combines three movements: the background slides from one side to the other, zooms from 100% to 200%, and its hue shifts by 30 degrees. The result is a gradient that flows and changes color slowly.

> **Note:** `liquid` animates the `filter` of the element, so it replaces any blur applied with `blur()` and `type: 'blur'` while it runs.

### Defaults

```ts
{
  duration: '8s',
  easing: 'ease-in-out',
  iterationCount: 'infinite',
}
```

### Examples

#### Flowing gradient

A four-color gradient that drifts and changes hue.

<XeerpeDemo example="liquid-flow" />

```ts
new Builder()
  .linearGradient({
    colors: [
      '#06b6d4',
      '#6366f1',
      '#d946ef',
      '#f97316',
    ],
    angle: '135deg',
  })
  .liquid()
  .toStyle()
```

## Float

Moves the whole element up by 10 pixels and back down, like it is floating. It pairs well with `glow()`, because the light moves with the element.

### Defaults

```ts
{
  duration: '6s',
  easing: 'ease-in-out',
  iterationCount: 'infinite',
}
```

### Examples

#### Floating card

A panel with a soft glow that rises and sinks.

<XeerpeDemo example="float-card" />

```ts
new Builder()
  .linearGradient({
    from: '#1e293b',
    to: '#0f172a',
  })
  .glow({
    color: 'rgba(56,189,248,0.5)',
    amount: '40px',
    y: '20px',
  })
  .float()
  .toStyle()
```

## Drift

Moves the background from the top left to the bottom right and back. Like `shimmer`, it needs a background larger than the element. When the gradient has no `backgroundSize`, `drift` widens it to `'300% 300%'` for you, so the movement reveals different parts of the gradient. Set your own `backgroundSize` to change it.

### Defaults

```ts
{
  duration: '10s',
  easing: 'ease-in-out',
  iterationCount: 'infinite',
}
```

### Examples

#### Wandering gradient

A multi-color gradient three times larger than its element, slowly sliding across it.

<XeerpeDemo example="drift-gradient" />

```ts
new Builder()
  .linearGradient({
    colors: [
      '#0ea5e9',
      '#6366f1',
      '#ec4899',
      '#f59e0b',
    ],
    angle: '135deg',
    backgroundSize: '300% 300%',
  })
  .drift()
  .toStyle()
```

## Combining animations

You can add more than one animation to the same chain. They run at the same time, each with its own options.

<XeerpeDemo example="combo-drift-plasma" />

```ts
new Builder()
  .linearGradient({
    colors: [
      '#0ea5e9',
      '#6366f1',
      '#ec4899',
      '#f59e0b',
    ],
    angle: '135deg',
    backgroundSize: '300% 300%',
  })
  .drift({ duration: '12s' })
  .plasma({ duration: '16s' })
  .toStyle()
```

### Good to know

- **Same property, last one wins.** Two animations that change the same property do not add up. `float` and `rotate` both animate `transform`, so with `.float().rotate()` the element only rotates, and with `.rotate().float()` it only floats.
- **Only gradients move by default.** `breathe`, `aurora`, `liquid`, `shimmer` and `drift` change the size or the position of the background. The `target` option chooses which layers follow: `'gradients'` (the default) moves the gradients and keeps patterns and effects in place, `'patterns'` slides only the patterns over a still gradient (for the position animations `shimmer`, `drift` and `liquid`), and `'all'` moves every layer. For example, `.shimmer({ target: 'all' })` makes a grid slide together with the gradient. `toStyle()` writes a few `--xeerpe-*` custom properties for this, so use the style object it returns together with the xeerpe stylesheet, and update both when you upgrade.
- **Filters are replaced.** `liquid` and `plasma` animate `filter`, which replaces any blur applied with `blur()` and `type: 'blur'` while they run.

## Reduced motion

The animations do not check the user's motion preferences on their own. To respect `prefers-reduced-motion`, add this rule to your stylesheet. It stops every xeerpe animation for the users who asked for less motion.

```css
@media (prefers-reduced-motion: reduce) {
  [style*='xeerpe-'] {
    animation: none !important;
  }
}
```

## Types reference

```ts
type AnimationType =
  | 'pulse'
  | 'rotate'
  | 'breathe'
  | 'aurora'
  | 'shimmer'
  | 'liquid'
  | 'plasma'
  | 'float'
  | 'drift'

interface AnimationOptions {
  duration?: string
  easing?: string
  direction?:
    | 'normal'
    | 'reverse'
    | 'alternate'
    | 'alternate-reverse'
  iterationCount?: number | 'infinite'
  target?: 'gradients' | 'patterns' | 'all'
}
```
